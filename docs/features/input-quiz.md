# 輸入題測驗

## 狀態

暫緩開發。

目前先不把輸入題列為近期開發重點。原因是中文翻譯常有多種合理答案，如果使用完全相等比對，容易把合理答案判錯，導致學習體驗變差。

## 目標

讓使用者可以透過輸入中文翻譯來回答英文單字題目。

## 解決問題

資料模型已經支援 `quiz_mode: "input"`，但輸入題需要先重新設計答案判定方式，才適合成為正式功能。

目前主要問題不是 Rails 實作，而是產品體驗：

- 同一個英文單字可能有多個合理中文翻譯。
- 使用者可能理解正確，但輸入的文字和標準答案不同。
- 若系統直接判錯，會讓使用者覺得挫折。
- 錯誤判定也會影響 Dashboard 與錯題統計的可信度。

## 功能範圍

以下是未來重新啟動時可能包含的範圍：

- 顯示一個英文單字。
- 讓使用者輸入中文答案。
- 每次作答都建立一筆 `QuizRecord`，並記錄 `quiz_mode: "input"`。
- 支援分類與難度篩選。
- 顯示參考答案，讓使用者理解標準翻譯。
- 在目前單字旁顯示收藏按鈕。

## 暫不包含

- 第一版不使用完全相等比對作為唯一判定方式。
- 語音輸入。
- AI 自動批改。

## 可能路由

- `GET /quiz`
- `POST /quiz/answer`

## 可能方案

### 方案一：自評模式

使用者輸入答案後，系統顯示參考答案，再由使用者自己選擇「答對」或「答錯」。

這是目前最推薦的方向，因為它最符合語言學習中的主動回想，也能避免同義答案被誤判。

### 方案二：多答案白名單

替每個單字維護多組可接受答案，例如：

- `遷移`
- `資料庫遷移`
- `migration`

這可以保留自動判分，但需要額外維護答案資料。

### 方案三：模糊比對輔助

忽略空白、標點或全形半形差異，降低格式造成的誤判。

這只能作為輔助，不能完整解決中文語意判斷問題。

### 方案四：AI 判斷答案合理性

使用 AI 判斷使用者輸入是否接近標準答案。

這可能帶來最佳體驗，但需要考慮 API 成本、速度、穩定性與判定一致性。

## 未來實作步驟

1. 先決定輸入題採用自評、自動判分，或混合模式。
2. 確認目前 route 與 controller 行為。
3. 補完整或調整 `QuizController#index`。
4. 補完整或調整 `QuizController#answer`。
5. 新增或調整輸入題 view。
6. 確認收藏按鈕行為。
7. 新增答對與答錯情境的測試。

## UX 備註

- 答案輸入框在手機上應該容易點選與輸入。
- 作答結果應該避免讓合理答案被機械式判錯。
- 作答後應該明確提供下一題操作。
